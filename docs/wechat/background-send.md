# 微信后台发送（0.2.2）

`wechat_write_mode=background` 是默认模式。读取、定位、写入、发送均绑定已验证的微信 HWND/PID。文字通过 Qt 顶层窗口的 WM_CHAR 输入，发送通过点击当前截图检测到的绿色发送按钮完成，不依赖系统前台，不向 agent 或其他前台程序注入按键，也不改变系统剪贴板。

## 检查顺序

1. 重新观察实际布局，定位唯一列表项，精确匹配标题。
2. 读取输入框：在原始裁剪图周围增加 32px 边距，避免 OCR 漏掉贴边文字。发送按钮已启用但 OCR 没读到文字时，必须报不可验证，不能判空。
3. 空输入框才能输入；已有草稿只有与本次获授权内容完全匹配（原有空白规范化规则）时才能直接继续。不同内容保留并停止，禁止追加。
4. 后台点击编辑区域，逐字符验证 HWND/PID、布局和目标标题，再向微信顶层窗口发送字符。
5. OCR 读回必须与请求正文一致。再次验证目标标题，后台点击从截图观测到的发送按钮。
6. 必须同时确认按钮不再启用、输入框已清空。进入发送调用后的异常仍为 uncertain，绝不通过前台重试造成重复发送。

## 支持范围

- 当前后台路径支持不含控制字符的单行 Unicode 文本。换行、制表符等在写入前明确拒绝，避免被当作提交或导航。多行文本可选择下面的前台模式。
- 微信可以被 agent 等其他窗口覆盖，但须保持已登录、可见且非最小化，并且能由 PrintWindow 截取；不可见、最小化、失去窗口身份或布局变化时停止。
- 未绕过收件人精确匹配、审批策略、幂等记录或窗口归属检查。
- 可显式配置 `wechat_write_mode=foreground`，保留自动尝试 SetForegroundWindow 后的受保护输入。Windows 拒绝激活则返回 not_sent/foreground_lost；不强行降级，也不在 uncertain 后自动换路径重发。

## 实际排查证据

后台 WM_CHAR 已生效，最初误以为输入失败的原因是原输入框 OCR 返回空，但截图显示已有文字。三份测试草稿均未提交，已在精确确认内容后清理。增加图片边距后，本地 OCR 能准确读回完整正文。后台测试前后系统前台窗口均不是微信。
